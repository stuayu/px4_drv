# MyGica T230C の利用

対象は USB `0572:C68A` の MyGica T230C2 です。WinUSB / macOS の DriverHost_PX4 と Linux カーネルモジュールから、ISDB-C を DVB-C の設定で受信します。ISDB-T、ISDB-S、DVB-T/T2 は受信対象に含みません。

## ファームウェア

Si2168 D60 と Si2141 のファームウェアは同梱していません。利用者が [dvb-firmware-osmc](https://github.com/osmc/dvb-firmware-osmc) から `dvb-demod-si2168-d60-01.fw` と `dvb-tuner-si2141-a10-01.fw` を取得し、DriverHost_PX4 と同じフォルダーへ配置します。

Si2141 の ROM ID が `0x60` の場合は `dvb_driver_si2141_rom60.fw`、`0x61` の場合は `dvb_driver_si2141_rom61.fw` を先に探します。該当ファイルが見つからない場合、または別の ROM ID の場合は `dvb-tuner-si2141-a10-01.fw` を使います。`DeviceDefinition` の `Si2168Firmware`、`Si2141FirmwareRom60`、`Si2141FirmwareRom61`、`Si2141Firmware` でそれぞれのパスを指定できます。相対パスは DriverHost_PX4 と同じフォルダーを基準にします。

起動時にファイルを 17 バイトレコードとして検査します。候補が見つからない場合は検出した ROM ID をエラーに記録します。ROM 固有ファイルの形式が不正な場合は、そのファイルを検査できるようエラーを返します。

## Linux で使う

Linux 版は T230C2 を1受信機として登録し、`/dev/px4video*` から ISDB-C の TS を出力します。チャンネル変更時は USB 転送と TS 同期状態をリセットします。TSMF、TLV、NULL パケットは選別せず、そのまま受信側へ渡します。

カーネルの firmware 検索先へ、次のファイルを配置します。

- `dvb-demod-si2168-d60-01.fw` (必須)
- `dvb_driver_si2141_rom60.fw` (ROM ID `0x60` 用、任意)
- `dvb_driver_si2141_rom61.fw` (ROM ID `0x61` 用、任意)
- `dvb-tuner-si2141-a10-01.fw` (ROM 固有ファイルが無い場合の代替)

```bash
sudo install -m 0644 dvb-demod-si2168-d60-01.fw /lib/firmware/
sudo install -m 0644 dvb-tuner-si2141-a10-01.fw /lib/firmware/
```

カーネル標準の `dvbsky` ドライバーも同じ USB ID を登録します。先に `dvbsky` がデバイスを bind している場合は、その bind を解除してから `px4_drv` をロードします。通常の px4_drv のビルド・インストール手順は [README](../README.md)を参照してください。インストール後にデバイスを挿すと `/dev/px4video*` が作成され、udev 規則は `video` グループへアクセス権を設定します。

Si2141 の ROM ID が `0x60` / `0x61` の場合は対応する ROM 固有ファイルを先に要求し、ファイルが見つからないときは A10 ファイルを使います。それ以外の ROM ID では A10 ファイルを要求します。Si2168 と Si2141 のファームウェアは再配布しません。

### Linux 版の確認範囲 (2026-11-01)

確認済みの範囲は macOS のユーザー空間ビルドと CTest、Ubuntu 24.04 (kernel 6.8) でのカーネルモジュールのビルドです。T230C2 の初期化、ISDB-C ロック、連続 TS 受信は未確認です。Linux での採用前に `0572:C68A` 実機の受信確認が必要です。

## Windows で WinUSB を割り当てる

デバイスマネージャーで T230C を選び、`winusb/pkg/inf/T230C.inf` を指定してドライバーを更新します。管理者 PowerShell から `pnputil /add-driver T230C.inf /install` を実行する方法もあります。`px4_drv_winusb.cat` は `T230C.inf` を含めて再生成・署名済みです。自己署名のため、事前に `cert-install.jse` などで px4_drv のルート証明書を信頼済みにしておく必要があります。挿したままの T230C に INF を適用すると、Geniatech ドライバーを開いているアプリケーションがある場合に再起動待ちになります。その場合は T230C を抜き差しすると WinUSB に切り替わります。

Geniatech ドライバーへ戻す場合は、管理者 PowerShell で `pnputil /enum-drivers` を実行して Geniatech の公開名 (`oemN.inf`) を確認し、`pnputil /delete-driver oemN.inf /uninstall` を実行した後、デバイスマネージャーで元のドライバーを再インストールします。削除前に対象プロバイダーと INF 名を確認してください。

## 設定

Windows の `winusb/pkg/DriverHost_PX4/DriverHost_PX4.ini`、macOS の `macos/DriverHost_PX4.ini` に `VendorId=0x0572`、`ProductId=0xC68A` の定義があります。`XferPackets`、`MaxUrbs`、`ReceiverMaxPackets` は転送粒度、並列数、受信バッファーの調整値です。ISDB-C の選局には `ExperimentalISDBC=true` が必要です。BonDriver を使う場合は `BonDriver_T230C.ini` と `BonDriver_T230C-C.ChSet.txt` を配置します。チャンネル表は PX-MLT 系の `BonDriver_PX4-C.ChSet.txt` と同じ形式 (物理チャンネル番号と TSMF の TS 番号) で、中心周波数は物理チャンネル番号から BonDriver が求めます。TSMF の TS は DriverHost の共通の TSMF フィルターで選び、ヘッダーのない搬送波は TS0 の指定でそのまま出力します。分割 TLV を運ぶ TS は、TSMF のヘッダーの stream_type から判断して TLV を取り出して出力します。

T230C を複数台つなぐと、DriverHost はすべてを受信機として登録します。BonDriver は空いている T230C から順に使います。初期化に失敗した T230C は登録から外れ、ログに `px4::DeviceManager::Add` の行が残ります。この行には、失敗した段階、戻り値、デバイスパスが出ます。

## 制限と実機確認

Si2168 の公開カーネルコードには ISDB-C Annex C の選択、roll-off 0.13 の指定、QAM コンスタレーションの指定がありません。DVB-C 6 MHz とシンボルレートを設定し、変調方式は復調器の自動判定に任せる実験的な対応です。CNR は Si2168 DVB-C 状態応答の 0.25 dB 単位からミリベルへ変換します。BER とパケットエラーは未対応です。

## 実機確認 (2026-10-31)

検証環境は Windows 11 (26100)、Visual Studio Community 2026 (ツールセット v145 を指定してビルド)、T230C (USB `0572:C68A`、Si2141 は A10 ファームウェア) です。CATV 受信レベルは C/N 約 30〜37 dB でした。

| 項目 | 結果 |
|---|---|
| ファームウェアの受理と初期化 | Si2168 D60 / Si2141 A10 とも成功 |
| ISDB-C のロック (DVB-C 6 MHz・5274 ksym/s・QAM 自動判定) | 279 / 369 MHz の通常 TS、587 / 605 MHz の 4K (TSMF) とも成功。Annex C を指定しなくても受信できた |
| 選局からロックまでの時間 | 165〜223 ms (30 回の中央値 187 ms) |
| 通常 TS の再選局 (`channel_switch_stress`、279 ↔ 369 MHz、30 回 × 3 秒) | 選局失敗 0、同期エラー 0、TEI 0、CC エラー 計 8 (1 回あたり最大 2、選局直後) |
| CATV-TLV 空間の TLV 出力 (587 MHz、6 秒) | 37 Mbps、TLV パケット 66,449 個が長さどおりに連続 |

上表は、TSMF の TS を相対 TS 番号・slot offset・TLV 出力の指定で選んでいた以前の実装での結果です。現在の実装は、PX-MLT 系と共通の TSMF フィルターで TS 番号から TS を選び、TLV の出力もヘッダーから判断します。この実装と現在のチャンネル表での T230C の実機確認は未実施です。

確認の過程で次の問題を直しました。

- 選局のたびに配信バッファーを停止していたため、DriverHost の配信接続が最初の選局で終わり、以後の TS がクライアントへ届かなかった。選局時は USB 転送だけを止め、配信バッファーの開始・停止はクライアントの SET_CAPTURE だけで行うようにした。
- ファームウェア読み込み後の最初の選局だけ、チューナーまたは復調器のコマンド応答待ちが期限切れ (`-ETIMEDOUT`) になる。選局コマンドは再送しても同じ状態になるため、TUNE の残り時間内で1回だけ送り直す。
- ChSet の UHF 帯 (U13〜U62) のチャンネル ID が 100 から始まり、C63 (50) との間が空いていた。チャンネルを番号順に列挙するアプリケーションが C63 で走査を止めるため、51〜100 に振り直した。
- ChSet の C23 が C22 と同じ物理チャンネル 12 (165 MHz) を指していた。正しい 22 (225 MHz) に直した。
- CATV によっては VHF 1ch (93 MHz) でもトラモジの TS を送っている。ChSet に `VHF` 空間 (空間 2) を追加した。既存の空間 0 と 1 のチャンネル ID は変わらない。

2台目の T230C は、1台目と同じ USB 2.0 ハブにつなぐと、初期化の途中でコマンドに応答しなくなった。GPIO でチューナーの電源を入れる段階、または Si2168 の初期化で止まり、以後は USB デバイスを再起動するまで応答しない。給電不足が疑われるため、複数台を使う場合は PC 本体の USB ポートかセルフパワーのハブにつないでください。

未確認の項目は、30 分以上の連続受信、抜き差し後の再利用、macOS での実機動作、64QAM の搬送波、BER とパケットエラーの取得 (未実装) です。長時間録画での品質は、対象地域の十分な受信レベルで測定してください。
